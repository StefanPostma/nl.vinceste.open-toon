# ADR-0003: HTTP client on the built-in `fetch`, `ToonError` model, no runtime dependencies

* Status: accepted (2026-11-12); **revised rev 2 (2026-11-12)** after the design reviews (F-08, R-10, R-11): `Connection: close`, body cancellation and timer clearing on every path, per-request `AbortController` instead of `AbortSignal.any` with the long-lived epoch signal, `normalizeAddress` hardening (IPv6, `https://`, non-strings), `aborted` has a user message. Revision log: `docs/sdlc/archive/05b-design-revision-log.md`
* Related: `05-architecture.md` §4, §7; HS-02, HS-03; NFR-04, NFR-05, NFR-08, NFR-16; FR-03; `03-reuse-inventory.md` T1-T4, §8; ADR-0005 (teardown), ADR-0013 (adapter)

## Context

`device.js:4` requires `request-promise-native`, which is not declared in `package.json` and only resolves through `homey-wifidriver`'s hoisted dependencies (`request` is deprecated). `ToonDevice extends WebAPIDevice` but never calls `super.onInit()`, so nothing of the library is used, and the one library path that runs (`onDeleted`, `device.js:488-491`) throws. Requests have no timeout (`onInit` stalls for minutes on a wrong IP) and URLs are built by string concatenation of the user-typed address (`device.js:94` etc.). Homey states that the built-in `fetch` is "the preferred approach for new code" (HS-02); Node 22 is the runtime from firmware 12.9.0 (ADR-0004).

## Decision

`lib/toon/client.js`: `new ToonClient({ host, fetch, timers: {setTimeout, clearTimeout}, timeoutMs = 5000, maxBytes = 2 MiB })`, one method `get(endpoint, { signal, priority })`.

* **Address**: `normalizeAddress(input)` in `lib/toon/address.js` never throws: a non-string yields `{ok:false, reason:'invalid'}`; `new URL('http://' + candidate)` is wrapped in `try/catch` (`:99999` and bare IPv6 throw); the result must have `protocol === 'http:'`, `username === ''`, `password === ''`, `pathname === '/'`, `search === ''`, `hash === ''`; an `https://` prefix is rejected with its own reason (`error.address_https`, "The Toon speaks plain http; remove https://" / "De Toon gebruikt gewoon http; verwijder https://"); a bracketed or bare IPv6 literal is rejected explicitly in 2.0.0 (`error.address_ipv6`, "IPv6 addresses are not supported; use the Toon's IPv4 address" / "IPv6-adressen worden niet ondersteund; gebruik het IPv4-adres van de Toon") because no evidence of a Toon reachable over IPv6 exists and the Toon's embedded server behaviour on IPv6 is unknown; an optional `:port` is kept. FR-03's accepted forms are otherwise unchanged.
* URL via `new URL('http://' + host)` + `pathname` + `searchParams`; only `http:`.
* `fetch(url, { redirect: 'manual', headers: { 'Accept-Encoding': 'identity', 'Connection': 'close' }, signal })`; any 3xx is `ToonError('redirect')`. **`Connection: close`**: Node's `fetch` (undici) pools sockets per origin by default; the Toon's embedded HTTP server idle-socket policy is unknown, and a socket the Toon closed between a poll and the `refreshSoon(1500)` write would surface as `fetch failed` (`UND_ERR_SOCKET`/`ECONNRESET`), mapped to `network` and counted as a core failure. At a >= 10 s cadence pooling buys nothing, so one socket per request is the safer default. Verified on the dev machine (Node 25.9, 2026-11-12): Node's `fetch` passes the `Connection: close` request header through to the server and `Accept-Encoding: identity` is sent; CI repeats this on Node 22 (L1). HW item next to H4: keep-alive vs `Connection: close` against a real Toon.
* Timeout = a **per-request** `AbortController` aborted from the **injected** `timers.setTimeout`; the device's epoch signal (teardown/address change) is wired to it by an `abort` listener that is **added before the request and removed in `finally`**, so no dependent signal accumulates on the long-lived epoch signal (the review could not verify prompt release of `AbortSignal.any` dependents on Node 22; a listener we remove ourselves needs no such proof). Not `AbortSignal.timeout`: fake clocks must drive it and `lib/` must contain no global timer (lint `homey-app/global-timers`).
* **Every exit path releases its resources**: `clearTimeout` in `finally`; on 3xx, non-2xx, `too_large` and `bad_body` the response body is cancelled (`await res.body?.cancel()`), otherwise undici keeps the socket reserved and a Toon that answers 500 on `getDevices.json` for hours would leak one socket per cycle. L1 asserts `server.getConnections() <= 1` after 50 error responses and a stable `process.getActiveResourcesInfo()`; the 1,000-cycle L2 scenario asserts the epoch controller's listener count does not grow.
* Body streamed with a byte counter; over the cap -> abort + `too_large`. `JSON.parse(await text)` (the Toon serves `text/javascript`); non-object -> `bad_body`; `result === 'error'` -> `toon_error`.
* `ToonError extends Error { kind, status?, cause? }`, kinds `timeout | network | http | redirect | too_large | bad_body | toon_error | aborted | config`. No user text, no response body in the error. `lib/messages.js` maps every `kind` to en/nl locale keys, **including `aborted`** (`error.aborted`: "The request was cancelled because the device was removed or its address changed"), because a user-initiated task cancelled by teardown or an address change must reject with a localized message (ADR-0005); poll-cycle `aborted` results are still never logged, counted or shown.
* No retries in the client; the poller owns retry and back-off policy.
* `/water.html` is not a client method; the ToonWater feature owns that endpoint object.
* Runtime `dependencies: {}`; `homey-wifidriver`, `homey-log`, `request*` removed.

## Consequences

* Deterministic tests for timeouts and back-off under a fake clock; real-socket tests cover redirect, oversize, abort.
* Localised, cause-naming errors in Flows and settings (NFR-16).
* Hardware items: `Accept-Encoding: identity` vs default `gzip, deflate` on a real Toon (03 H4); keep-alive vs `Connection: close` (next to H4); content type of `/water.html` (03 H3). The mock Toon has an `idle-close` mode (closes idle sockets after 1 s) so the stale-socket path is exercised whichever header policy the hardware run prefers.
* The pair view and the pairing handlers `typeof`-check every field before use and render Toon-supplied readings with `textContent`, never `innerHTML` (ADR-0008).
* Alternatives rejected: `node:http` with a `>=5.0.0` floor (keeps Node 12/16 alive, no `fetch`, two runtimes to test); `undici`/`node-fetch`/`axios` (a dependency for nothing); retries inside the client (hides load from the NFR-03 budget); a custom undici dispatcher to disable pooling (a request header does the same without touching undici internals); "retry once uncounted on `ECONNRESET`" (hides a real fault class behind a retry; `Connection: close` removes the cause instead).
