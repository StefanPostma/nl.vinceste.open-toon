# ADR-0005: Poll scheduler, per-device lane with write priority, back-off, availability, cleanup

* Status: accepted (2026-11-12); **revised rev 2 (2026-11-12)** after the design reviews (`05a-*`): no in-flight abort for writes, cycle short-circuit on transport failure, refresh coalescing, teardown settles queued work, no optimistic write (amends `04` B-5), back-off floor, time-and-count availability (amends FR-81 AC1), NFR-08 AC2 amended, debug switch via `this.homey.env`. Revision log: `docs/sdlc/archive/05b-design-revision-log.md`
* Related: `05-architecture.md` §5; FR-16, FR-74, FR-80..84; NFR-03, NFR-08, NFR-09, NFR-12; HS-22, HS-25, HS-28; `04` R-10, B-1..B-3, B-5; reviews R-01..R-04, R-06, R-07, R-09, R-15, R-17, R-19, F-04

## Context

There is no polling at all today (`device.js` has only an unused `debounce` with a global `setTimeout`, `:569-586`); users were told to build timer Flows around the `update_*` cards (#5, #25). The device never goes unavailable (`device.js:497-519` dead overrides). `onInit` awaits four un-timed HTTP calls. `onDeleted` throws. Homey blocks Flow actions on an unavailable device (HS-25) and disposes `this.homey.setTimeout` timers on app destroy (HS-22). The first version of this ADR let a write **abort** an in-flight poll request; the robustness review (R-01) showed that an abort closes only the Homey-side socket while the Toon keeps executing the GET, so the Toon would see two requests at once and the in-process test double could not observe it.

## Decision

* **Scheduler**: one self-rescheduling `this.homey.setTimeout` chain per device, re-armed in `finally`; one in-flight cycle; first cycle 1 s + random 0-2 s after `onInit` returns; `onInit` never awaits the network.
* **Lane**: all Toon traffic of a device goes through one async queue with priority classes `write` > `refresh` > `poll` and **exactly one request in flight**. **A request in flight is never abandoned to make room for another request to the same host.** Aborts happen only on teardown and on an address change (epoch `gen++`), after which this device sends nothing more to that host. The cycle takes the lane **per group request** and yields between groups, so a queued write or refresh runs after the current request settles (<= 5 s) and before the next group. NFR-03 AC1 ("never two concurrent requests to one Toon") therefore holds per device as written and is measured by the mock's server-side `maxConcurrent()` (ADR-0013). **NFR-08 AC2 is amended**: a Flow action or capability set is *started* at the latest when the in-flight request settles (<= 5 s) and *settles* within its own 5 s timeout: <= 6 s when the Toon answers polls within 1 s (the normal case), <= 10 s under a pending poll timeout. Both bounds are asserted in L2.
* **Refresh coalescing** (B-3, FR-74 AC3): the lane holds at most one *pending* refresh per group; a later refresh for the same group joins the pending one and resolves with its result; a refresh for a group whose poll request is currently in flight joins that request. Ten `update_status` cards firing together produce one targeted cycle.
* **Cycle**: `activeGroups(featureState)` in order `thermostat` (critical) -> `power` -> `meters` -> feature groups; per-group try/catch for `http`, `bad_body`, `toon_error`, `redirect`, `too_large` (one endpoint failing never skips the others, FR-80 AC4). **If the critical group fails with kind `timeout` or `network`, the cycle ends after that group** (the host is down; the remaining groups are not requested). Groups may declare `every: n`, `absentOn404: {backoffMs}` and the water escalation of ADR-0006.
* **Interval**: `clamp(Number(poll_interval) || 30, 10, 3600)` s, resolved on read.
* **Back-off**: after `n` consecutive **core** failures, delay = `interval` for n = 1, 2; then `min(interval * 2^(n-2), max(300e3, interval))` (never shorter than the configured interval, NFR-03 AC2); reset on the first successful critical group. A request aborted by the epoch (teardown/address change) **neither increments nor resets** the counter. Water back-off: ADR-0006 item 6.
* **Availability**: only a failed `thermostat` group counts. `unavailable = (failures >= 3 && elapsed >= 90 s) || (failures >= 2 && elapsed >= 15 min)` with `elapsed = now - firstFailureAt`; four named constants, tuned in HW-10. `setUnavailable(__('offline'))` on the transition; `setAvailable()` on the first success; values never cleared; polling continues while unavailable. **FR-81 AC1 is amended** from "the third consecutive failed cycle" to this predicate: at 10 s a 30 s hiccup no longer flips the device (3 failures but < 90 s), at 3600 s the device is flagged after two failures (>= 15 min) instead of three hours.
* **Guards**: `gen` (address change, teardown), per-feature `featureGen` (toggles), `writeSeq` (a thermostat response requested before a write is dropped). Every response is checked against `_stopped`, `gen`, `featureGen` and `hasCapability` before any `setCapabilityValue`.
* **Writes**: setpoint validated finite and 6..30, rounded to 0.5, `Math.round(deg * 100)`, latest-wins single flight (<= 2 requests per slider drag). **No optimistic `setCapabilityValue`** (amends `04` B-5: the baseline wrote the value first because `request-promise-native` had no timeout, `device.js:243`; nobody can depend on it except as a flicker). The listener awaits the Toon; Homey stores the value when the listener resolves and leaves it unchanged when it rejects ([D] Device.html; the fake models this reading, HW-03/HW-13 confirm the tile). Success -> `writeSeq++`, `refreshSoon(['thermostat'], 1500)`; failure -> localized rejection + immediate thermostat refresh. `applyValues` stays the only `setCapabilityValue` door (NFR-01 AC2).
* **Cleanup**: `onUninit` and `onDeleted` call one idempotent `_teardown()`: `_stopped = true`, `gen++`, abort the epoch controller, `clearTimeout`, and **reject every task still queued in the lane or in the serial queue with `ToonError('aborted')`** so no Flow hangs. `lib/messages.js` maps `aborted` to `error.aborted` ("The request was cancelled because the device was removed or its address changed" / "Het verzoek is geannuleerd omdat het apparaat is verwijderd of het adres is gewijzigd"). "`aborted` is never logged, counted or shown" applies to **poll-cycle results only**; a user-initiated task (card, capability set, `onSettings`) that is cancelled rejects with that text. Every multi-step serial task checks `_stopped` before each Homey call. `_teardown()` never throws.
* **Never-rejects rule**: every entry point invoked by a timer or by Homey without an awaiting caller (`_cycle`, `refreshSoon`, the deferred status write, the FR-62 notification, warning and availability updates) is `async`, has a top-level `try/catch` that logs, and never rejects. An L3 grep asserts that every `this.homey.setTimeout(` callback calls a function on the never-rejects allow-list; the harness counters (NFR-01 AC1) remain the executable proof.
* **Logging**: transitions once on entry and exit; one short line per healthy cycle at most; payloads only when `debugPayloads` is true, computed once in `App#onInit` as `process.env.DEBUG === '1' || this.homey.env.OPEN_TOON_DEBUG === '1'` and handed to the devices. The first form is what `homey app run` sets; the second comes from an uncommitted `env.json` (`{"OPEN_TOON_DEBUG": "1"}`) present at `homey app install` time ([D] app.md "Environment variables"). Trade-off recorded: there is no runtime toggle on an installed build (the only SDK option would be a device/app setting, rejected as UI clutter for a developer switch); the hardware runs (HW-10) install with `env.json` present.

## Consequences

* Values refresh without Flows; the device recovers by itself after an outage; the Toon sees at most 4 sequential requests per interval and never two at once from one device.
* A write during a slow poll waits for that request instead of racing it on the Toon: simpler lane, no abandoned requests, one fewer class of concurrency bug (risk 6 downgraded).
* Two devices paired on the same Toon make two independent lanes and therefore up to two concurrent requests at that Toon (NFR-03 AC3 holds **per device**; documented in the README as unsupported; HW-10 notes the doubled load when the fixture-device pattern of `04` §10.2 is used).
* The Toon's nightly reboot (03 T6, single source) may flip availability once a night at defaults: accepted, constants tuned in HW-10.
* Rejected: `setInterval` (overlap risk, HS-22); B's cross-device `ClientPool` (no requirement, likeliest concurrency bug); retries inside the client; client-side abort of a poll to run a write (R-01: the Toon keeps executing the aborted GET, so the saving is illusory and NFR-03 AC1 would be false); a 3 s poll timeout to shorten the wait (false unavailability on a slow Toon 1).
