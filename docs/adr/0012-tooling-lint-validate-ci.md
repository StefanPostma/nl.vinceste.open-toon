# ADR-0012: ESLint 8 + Athom config, Homey CLI as a devDependency, CI matrix Node 22 (app) / Node 24 (CLI)

* Status: accepted (2026-11-12); **revised rev 2 (2026-11-12)** after the standards review (F-01, F-02, F-03, F-05, F-09, F-11): type-aware project covers the test tree, `@types/homey` required, lint canary, timer rule as error, `--max-warnings 0`, pack-content and locales checks in CI. Revision log: `docs/sdlc/archive/05b-design-revision-log.md`
* Related: `05-architecture.md` §12; NFR-01 AC2, NFR-02, NFR-06, NFR-10, FR-120; HS-06, HS-07, HS-16, HS-22; `02` findings 6-8, §9 items 9-10; `03` §8; ADR-0011

## Context

The HEAD manifest fails `homey app validate` at `debug` level, so it cannot be built or installed. There is no lint, no test, and the only workflow (`codeql-analysis.yml`) is disabled and uses retired actions. The Homey CLI needs Node >= 24 from 4.4.1 (registry `engines`, verified 2026-11-12: `homey@4.4.0` is the last with `>=22`), while apps run on Node 22 and the dev machine has Node 25. The CLI scaffold uses `eslint@~8.57.1` + `eslint-config-athom`; the CLI treats an app as TypeScript when `devDependencies.typescript` exists (source) or, per the docs, when a `tsconfig.json` exists. `homey app validate` needs no Docker for a JavaScript app (CLI source). Global installs are forbidden in this project.

Verified in source on 2026-11-12 (chief architect, independently of the review): `eslint-config-athom@4.0.2` `index.js` sets `"parser": "@typescript-eslint/parser"` for every file and extends `./rules/test` (an `overrides` block for `test/**/*.js` that loads `eslint-plugin-mocha` rules); `homey-app.js` sets `parserOptions.project` globally, `@typescript-eslint/no-floating-promises: ["error", {ignoreVoid: false}]` and `no-misused-promises: error`, and extends `plugin:homey-app/recommended`; `eslint-plugin-homey-app@3.0.0` `recommended` enables only `homey-app/global-timers` as **`warn`**, and that rule reports a `CallExpression` whose `callee.name` is `setTimeout`/`setInterval` (bare calls only; `global.setTimeout(...)` is not reported); `homey-app/homey-log` exists (reports `console.log`/`console.error`) but is not enabled by the config. `eslint-config-athom` depends on `typescript ^6.0.3` itself, so no `devDependencies.typescript` is needed. `homey-apps-sdk-v3-types@1.8.3` is the latest on npm. Two consequences: (1) with `parserOptions.project` set, `@typescript-eslint/parser` rejects every linted file that the project does not include, so a project that lists only `app.js`, `drivers/**`, `lib/**` makes `eslint .` fail on `test/**` and `scripts/**`; (2) without a declaration for the module `homey`, `Homey.Device` and every `this.setCapabilityValue(...)`, `setSettings`, `addCapability`, `card.trigger(...)` are typed `any`, and `no-floating-promises` ignores `any`-typed calls, so the rule would be a no-op for exactly the SDK calls NFR-01 AC2 is about.

## Decision

* **Lint configuration.** `.eslintrc.json`:
  ```json
  { "extends": "athom/homey-app",
    "parserOptions": { "project": "./tsconfig.eslint.json" },
    "rules": { "homey-app/global-timers": "error", "homey-app/homey-log": "error" },
    "overrides": [
      { "files": ["test/**", "scripts/**"], "rules": { "homey-app/homey-log": "off" } },
      { "files": ["test/**"], "rules": { "mocha/no-mocha-arrows": "off", "mocha/no-setup-in-describe": "off", "mocha/max-top-level-suites": "off", "mocha/no-hooks-for-single-case": "off", "mocha/no-exclusive-tests": "error" } } ] }
  ```
  (the tests use `node:test`, not Mocha; the Athom `test/**` override still applies, so the Mocha-interface rules that contradict `node:test` style are turned off and the useful ones kept; any further `mocha/*` rule that fires on the first run is added to this list, never silenced inline). `tsconfig.eslint.json` = `{"compilerOptions": {"allowJs": true, "checkJs": false, "noEmit": true, "types": ["node", "homey"]}, "include": ["app.js", "drivers/**/*.js", "lib/**/*.js", "test/**/*.js", "test/**/*.cjs", "scripts/**/*.js"]}` - the whole linted tree is in the project. The non-standard file name keeps the app out of TypeScript mode under both detection rules. Script `lint`: `eslint --ext .js,.cjs --max-warnings 0 --ignore-path .gitignore .` (a warning fails the job). `@types/homey` (`npm:homey-apps-sdk-v3-types@^1.8.3`) and `@types/node` are **required** devDependencies (ADR-0011), because the type-aware rules only see SDK promises through them.
* **What the lint proves, stated precisely.** `@typescript-eslint/no-floating-promises` flags un-awaited SDK promises *when the declarations are installed*; `homey-app/global-timers` flags **bare** `setTimeout`/`setInterval` calls. Neither is sufficient alone, so the L3 static layer adds: a **lint canary** (`test/static/lint-canary.test.js` runs `new ESLint()` from the `eslint` devDependency on `test/fixtures/lint/floating-promise-device.js`, a `Homey.Device` subclass with one un-awaited `this.setCapabilityValue(...)`, and asserts exactly one `@typescript-eslint/no-floating-promises` report; a second fixture with `global.setTimeout(...)` under `this.homey` absent asserts the layering grep catches what the lint does not); and the layering grep extended to `app.js` and `drivers/**` for `/\b(global(This)?\.)?set(Timeout|Interval)\(/` outside `this.homey.`. ADR wording is therefore "lint flags bare global timers and un-awaited typed SDK promises; the static tests cover the rest and prove the lint is live".
* **Validate**: `homey` CLI as a devDependency; script `validate`: `homey app validate --level publish`; run under **Node 24** (CI) or the dev machine's Node 25; never globally installed. After validation CI runs `git diff --exit-code app.json locales/` (Compose output must match the committed manifest, and `/locales` must be untouched: Compose deep-merges `.homeycompose/locales/` into `/locales/<lang>.json` when that directory exists, so it must never be created; an L3 test asserts it does not exist, ADR-0002). `--level verified` is a non-blocking extra step.
* **Pack content check**: after `validate`, CI runs `homey app build` and lists the produced `.homeybuild/` tree; the job fails on any path outside `app.js`, `app.json`, `drivers/`, `lib/`, `locales/`, `assets/`, `package.json`, `package-lock.json`, `LICENSE`, `README*.txt`. The CLI's default ignore list is `.*`, `.homeybuild`, `*.{ts,mts,cts}`, `tsconfig.json`, `env.json`, `*.compose.json`, `node_modules` (CLI source, [S]); `tsconfig.eslint.json` is **not** on it and is therefore added to `.homeyignore` (ADR-0011). [verify on the first CI run: `homey app build` needs no login; if it does, the check reads the CLI's ignore rules the same way the build does, via the committed `.homeyignore` plus the default list].
* **Tests**: script `test`: `node --require ./test/helpers/register.cjs --test "test/**/*.test.js"` on **Node 22**; coverage via `--experimental-test-coverage` with a >= 90 % line target on `lib/toon`, `lib/features`, `lib/engine` pure parts.
* **Manifest text checks (L3)**: `description.en !== name.en`, `description.nl !== name.nl`, `tags.en`/`tags.nl` non-empty (HS-13; the baseline description "Open - Toon®" repeats the name, a documented Store rejection reason); `drivers/open-toon/assets/icon.svg` not byte-identical to `assets/icon.svg` (HS-18; byte-identical today) - the icon check is on the **release checklist** and runs as a non-blocking L3 warning until new artwork exists (risk 10).
* **CI** (`.github/workflows/ci.yml`, replaces `codeql-analysis.yml`): job `test` on Node 22 (`npm ci --ignore-scripts`, `npm run lint`, `npm test`); job `validate` on Node 24 (`npm ci --ignore-scripts`, `npm run validate`, `git diff --exit-code app.json locales/`, build + pack listing). **Rev 3 (review finding SEC-02):** the optional job that used `athombv/github-action-homey-app-validate` is removed: the action is a Docker image on the floating tag `node:lts-alpine` whose entrypoint runs `npx homey app validate`, so it fetched the latest CLI at run time outside `package-lock.json`, next to the repository token, and its pinned commit was a branch head, not a release. `npm run validate` and `validate:verified` of the validate job cover the same checks with the locked CLI. `actions/checkout@v4`, `actions/setup-node@v4`. `.nvmrc` = `22` with a README note that the CLI needs 24+.
* **Release**: `homey app version <bump> --changelog.en ... --changelog.nl ...` maintains `.homeychangelog.json`.

## Consequences

* `npm run lint` is green on the first run on the whole tree, and the claim that NFR-01 AC2 is mechanically enforced is itself a test (the canary fails if the declarations go missing or the rule is downgraded).
* Validation is reproducible on any machine with `npm ci --ignore-scripts` and Node 24+; app code is proven on Node 22 by CI; the shipped bundle is listed and checked, not assumed.
* The ESLint 8 line is end-of-life but is what Athom scaffolds; migrating to the flat config of `eslint-plugin-homey-app` is a later, isolated change.
* If the first CI `validate` run shows the CLI flipped the app into TypeScript mode despite `tsconfig.eslint.json`, the fallback is to drop `parserOptions.project` and the two type-aware rules (documented in the workflow); the canary then fails loudly, which is the intended signal.
* Rejected: pinning `homey@4.4.0` to run on Node 22 (stale `homey-lib` schema); `homey-lib` called directly without the CLI (cannot compose); ESLint 9 flat config now (03 J14); an `overrides` block that sets `parserOptions.project: null` for `test/**` (would exempt the tests from `no-floating-promises`, and un-awaited promises in tests are the most common source of false-green scenarios).
