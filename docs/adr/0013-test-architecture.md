# ADR-0013: Test architecture without hardware (pure parsers, client, mock Toon, fake Homey, scenarios, static checks)

* Status: accepted (2026-11-12); **revised rev 2 (2026-11-12)** after the design reviews: `fetchAdapter` contract (R-08), server-side concurrency counter (R-01), count-based resource assertions (R-20), outbound-module grep (R-21), never-rejects grep (R-09), hostile payload fixtures (R-12), lint canary (F-02), compose/locales and pack checks (F-05, F-09), contract exceptions (ADR-0017), new L2 scenarios from every finding. Revision log: `docs/sdlc/archive/05b-design-revision-log.md`
* Related: `05-architecture.md` §13; NFR-01, NFR-06, NFR-12, NFR-15, FR-24, FR-76, FR-100, FR-113; `04` §10.1 (CT-01..CT-08); `03` §4.5 (fixture summary); ADR-0012, ADR-0017, ADR-0018

## Context

The owner wants everything verifiable against mocks now and a hardware plan later. There is no test, no mock and no CI in the repo; the earlier scratch harness no longer exists and must be rebuilt inside the repo. `require('homey')` resolves only inside the Homey runtime/CLI build (HS-03). Homey runtime behaviour that the docs do not state (U1-U13) can be wrong identically in code and fake. The robustness review showed that an in-process `fetch` double that ignores `signal`, uses real timers for delays, or forgets a request on client abort makes the abort, timeout and concurrency scenarios pass vacuously.

## Decision

Everything runs offline on Node 22 with `node --test` in under 60 s; `test/helpers/register.cjs` hooks `Module._resolveFilename` so `'homey'` resolves to `test/helpers/fake-homey/index.js`, and installs `unhandledRejection`/`uncaughtException` counters that fail the file when non-zero.

**`fetchAdapter(handler, {timers})` contract** (the in-process double of `globalThis.fetch`): (a) returns real `Response` objects; (b) schedules `delayMs` on the **injected** `timers.setTimeout`, never on a real timer, so slow/timeout scenarios run under the fake clock; (c) honours `signal`: an abort while waiting rejects the pending promise with an `AbortError`, an abort while the body streams cancels the `ReadableStream`; (d) **the handler keeps "running" after a client abort** (its end time is recorded when its `delayMs` elapses on the fake clock, not when the client left), and the mock records `{start, end, abortedByClient}` per request and exposes `maxConcurrent()` (server-side overlap) and `openHandlers()`; (e) passes request headers through so `Connection: close` and `Accept-Encoding: identity` are visible in the request log. An L1 **adapter-equivalence test** runs the same handler through `fetchAdapter` and through `node:http` + real `fetch` for the three behaviours abort-while-waiting, abort-while-streaming and server-side completion after client abort, and asserts the same observable results, so the adapter is proven equivalent on exactly the behaviours the L2 scenarios rely on.

**Resource assertions (NFR-12)** are counts, not bytes: after 1,000 cycles exactly one armed timer per device (fake clock queue), epoch controller listeners <= 1, lane queue length 0, `openHandlers() === 0`, `process.getActiveResourcesInfo()` unchanged. A heap check runs only under `--expose-gc` as a non-blocking job.

A synthetic fourth feature is registered in one scenario to prove the engine is feature-agnostic. Tests that rest on an unverified Homey or Toon behaviour carry the `HW-xx` id in their title.

## Consequences

* All `[M]` requirements have an executable check; the hardware backlog is exactly the set of `HW-xx`-tagged assumptions.
* The abort, timeout, teardown and concurrency scenarios are real tests: the adapter cannot pass them by forgetting a request, and NFR-03 AC1 is measured on the server side.
* The fake Homey is our reading of the docs: wrong readings show up on hardware, not in CI; the HW tags make that list explicit.
* No test dependency is added; the mock Toon doubles as a manual target for `homey app run` against the real Homey (Docker `--network host` may be needed, 02 §9 item 12).
