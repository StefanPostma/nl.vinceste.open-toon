## 1. Idea and decisions

`app.js`, `driver.js`, `device.js` only adapt Homey hooks. Behaviour lives in `lib/`, four layers, dependencies point downward. Pure layers import neither Homey nor `fetch`; side effects enter through one injected `services` object built in one composition root. ToonWater is a **feature object** with a fixed shape hosted by a generic runtime; core code never mentions water.

| Id | Decision | Why |
|---|---|---|
| DB-1 | `compatibility >=12.9.0`, built-in `fetch`, zero runtime deps | Node 22 everywhere (02 HS-01/02/14). Cost: older firmware stays on the old build (04 R-26). |
| DB-2 | `Feature` = plain object, registered in `lib/features/index.js` | Keeps water out of core; a 2nd feature (export power, FR-25, opt-in per OQ-06) reuses it. |

## 3. Device lifecycle

`onInit(){ this.rt = new ToonRuntime({device:this, services:this.homey.app.services, features:[toonwater]}); await this.rt.init(); }`; `onSettings`, `onDeleted`, `onUninit` forward to `rt`. No `onAdded`/`onRenamed` (pairing sets everything).

| Step | What happens |
|---|---|
| 1 `migration.run` | Offline, no network (04 M-1..M-7, R-32). `planMigration({capabilities, settings, store})` (pure) -> `{toonwater, setSettings?, add[], options[], marker}`, applied through `serialQueue`, `store.migrationVersion` written **last**; a failure is logged and retried next start, never makes the device unavailable. `ALWAYS = [target_temperature, measure_temperature, temperature_state, meter_power.peak, meter_power.offPeak, measure_power, meter_gas, alarm_water.hotwater, burner_state]`; the water trio comes from the feature. Never "all manifest capabilities" (04 R-01); never removes; keeps era-0 `meter_power` and unknown extras; `addCapability` only here or in a toggle (HS-30). |
| 2 `readConfig` | `{address: normalizeAddress() or null, intervalMs: clamp(Number(poll_interval)\|\|30, 10..3600)*1000, enabled:{toonwater}}`. Defaults resolved on read, **never persisted** (FR-112, 04 U3/R-29); stored `address` never rewritten (R-30). `null` (`''`, `0.0.0.0`, invalid) -> `unconfigured`: `setUnavailable(__('address_missing'))`, no polling (FR-03 AC3). |
| 3 housekeeping | `warnings.sync()` (`computeWarning(flags)` is pure and owns the single warning slot: address missing > ToonWater not found, so clearing one never clears the other); `status.sync()`. |
| 4 listeners | `registerCapabilityListener` for `target_temperature`, `temperature_state` (kept, 04 C-CAP-5). |
| 5 `engine.start` | First cycle after random 0-2 s via `services.timers`. **`onInit` returns without awaiting any request** (NFR-08 AC1). |

**Poll loop** (`PollEngine`): one self-rescheduling timer chain per device (no `setInterval`), in-flight guard, generation counter `gen`. A cycle runs `[thermostat(critical), power, meters, ...enabled feature groups]` strictly sequentially. Group shape `{id, critical, optional, every, run(ctx) -> {values, meta}}`; a throwing group is caught per group (FR-80 AC4) and becomes `CycleReport {gen, groups:{id:{ok,changes}|{ok:false,error}}, coreOk}`. Then `availability.step`, `status.sync`, `triggers.fire(changes)`, `nextDelay(interval, coreFailures, rand)` (x2 per consecutive core failure, cap 300 s, NFR-03 AC2), reschedule in `finally`. Default 30 s, 3 requests per cycle (4 with ToonWater).

**Availability** (`availability.js`, pure state machine): only a failed `thermostat` group counts. `setUnavailable(__('offline'))` on the 3rd consecutive failed cycle (and >= 90 s, parameter), `setAvailable()` on the first success, polling continues with back-off meanwhile, values are never cleared (FR-81). Water/meter failures never count (FR-57 AC3). The Toon's nightly reboot (03 T6, single source) may flip availability once a night; threshold tuned in `01:HW-10`.

**`CapabilityWriter`** (the only `setCapabilityValue` door, NFR-01 AC2): drops ids the device lacks (`hasCapability`: a late water response after removal is discarded, FR-53 AC3; `meter_power` written only if present, 04 R-25), non-finite numbers and out-of-enum strings (C-CAP-6), and values with a stale `gen` (address change, teardown); change detection against `getCapabilityValue` (first `null` -> value is no change; after a restart the stored value is the baseline, FR-70 AC4); awaits with `.catch(log)`; returns `Change[] {id, prev, next}`. A write-epoch stops a poll that began before a write from reverting it (FR-16 AC3).

**Writes** (`writes.js`): setpoint validated 6..30, rounded to 0.5, sent as integer `Math.round(c*100)` (FR-11 AC1), latest-wins coalescer (one in flight + one trailing, FR-16 AC1); `changeSchemeState` via `SCHEME_SEQUENCES`; program `state=1/0`. A write **preempts** in-flight poll GETs (the gate aborts them, kind `aborted`, not a failure; the cycle ends early and the post-write `refreshSoon(['thermostat'],1500)` re-runs it), so it settles in <= 5 s (NFR-08 AC2).

**`onSettings({newSettings, changedKeys})`**: never `getSetting` inside (old values until it resolves; inference from 04 section 6). (1) validate synchronously, throw a localized `Error` for bad `address` / `poll_interval` (FR-82 AC1, FR-83 AC1); (2) `return serialQueue.run(...)`: `toonwater_enabled` changed -> reconcile capabilities and enable/disable the feature (section 5); `address` changed -> `gen++`, abort in-flight, new client, reset all back-offs, immediate cycle, re-probe ToonWater if enabled (FR-82 AC2); `poll_interval` -> `engine.setInterval`. Returns the localized message (FR-59). Read-only status labels are written with `setSettings` (does not call `onSettings`), on transition only; `last_success` at most every 5 min (FR-85).

**`onDeleted` / `onUninit`**: one idempotent `rt.destroy()`: `stopped=true`, `gen++`, abort in-flight, clear timers; never throws; late responses die on the `gen` check (FR-84 AC1-3). Warnings are cleared by the code that ends the condition (probe success, disable, init while disabled), not at shutdown.

## 4. HTTP client and error model

`ToonClient({address, fetch, timers, timeoutMs:5000, maxBytes:2 MiB, gate})`. URL via `new URL('http://'+host)` + `pathname` + `searchParams` (NFR-04 AC1); `normalizeAddress` accepts `host[:port]`, strips `http://` and `/`, rejects `0.0.0.0`, paths, `?`, `@`, spaces, port > 65535 (FR-03). `request(path, query, {priority})` = `fetch(url, {redirect:'manual', headers:{'Accept-Encoding':'identity'}, signal})`; the timeout is an `AbortController` driven by **injected** timers (not `AbortSignal.timeout`, so fake clocks work); 3xx -> `redirect`; body read by stream with the byte cap; `JSON.parse(text)`; must be an object; `result:'error'` -> `toon_error`. No retries. Core endpoint methods only: `getThermostatInfo`, `getCurrentUsage`, `getDevices`, `setSetpoint`, `changeSchemeState`; `/water.html` is **not** in the client.

`ToonError {kind, status?, cause?}`, `kind` in `timeout | network | http | redirect | too_large | bad_body | toon_error | aborted`; `isNotFound(e)` = `http` + 404; `aborted` is never logged, counted or shown; `userMessage(e, i18n)` maps kind to locale keys (`error.timeout`, `error.http` + status, `error.not_toon`, ...), never raw text (NFR-16). `ClientPool.get(address)` returns one client per Toon with a serial gate (writes first, poll GETs abortable).

## 5. ToonWater opt-in, end to end

`lib/features/toonwater/index.js` exports `{id:'toonwater', settingKey:'toonwater_enabled', capabilities:['measure_water','meter_water.today','meter_water.total'], pollGroup(ctx), probe(client), status(state), triggers:[{cardId:'measure_water_changed', capability:'measure_water', token:'measure_water'}], guard(device)}`. `endpoint.js` is the only file containing `/water.html` (FR-60 AC3, grep test). `parse.js` is pure: `parseWater(json) -> {values}`: `flow` as L/min, `value` and `total` / 1000 to m3 at 3 decimals, every field independently optional, negative or non-finite ignored, `avgValue` ignored (FR-58). Provenance header: derived from this repo's GPL-3.0 PR #21 (`f705a70`) and the interface in 03 section 5.3, no code from unlicensed repos (NFR-11).

| Aspect | Behaviour |
|---|---|
| Setting | `toonwater_enabled` checkbox, default `false`, group "ToonWater (optional add-on)" with the FR-59 hint, plus read-only label `toonwater_status` (Off / Detected / Not found (HTTP 404) / Toon not reachable / Unexpected response). |
| New device | Driver `capabilities` = `ALWAYS` (FR-51 AC1). `deviceRecord.build()` -> `{name, data:{id}, settings:{address, toonwater_enabled:false}, store:{migrationVersion:1}, capabilities}`; water caps only if the user ticked the detected-only pair checkbox. Zero `/water.html` requests, no water log line, no warning. |
| Existing device | Migration decides once, from capabilities only (04 7.4): none of the 3 -> `false`, nothing added; any -> `true`, missing ones added, nothing removed. `setSettings` does not call `onSettings`, so the migration reconciles itself. The marker makes it one-shot: a later user "off" is never flipped back (FR-56 AC5). `alarm_water.hotwater` is **not** consulted (04 R-36). |
| Enable | `onSettings` under the queue: `addCapability` x3 (guarded), `setCapabilityOptions` from `driver.manifest.capabilitiesOptions` (water titles stay in the manifest superset, 02 W9), then an immediate `probe` (<= 5 s). Result messages per FR-59: detected / not_found (`setWarning` + status, capabilities stay, D-4) / unreachable (new key `toonwater.save_unreachable`, FR-55 AC5). First values land in the same call (FR-52 AC1). |
| Poll group | Exists only while enabled. Per-device `waterState {phase, nextProbeAt}` (instance state, HS-27): `ok` -> every cycle; HTTP 404 -> `not_found`, next probe in 15 min (<= 97/day), one info log on entry and exit (FR-57, NFR-09); 200 + bad body -> `unexpected`; timeout/network -> short back-off, status `unreachable` only if the thermostat group also failed. None of it touches `coreOk`. |
| Detection | `probe` is one code path for pairing, enable, address change and polling -> `detected | not_found | unexpected | unreachable`. 404 means "absent" (03 T8, M confidence; `01:HW-07`). The app never auto-disables (D-3). |
| Disable | Under the queue: abort the water request, `removeCapability` x3, drop `nextProbeAt`, recompute the warning, status Off, return the "removed, Flows need updating" message. Touches only the water group (FR-60 AC1); a late response is dropped by `hasCapability`. Re-enable restores the **same ids** (FR-54 AC4). |
| Cards (DB-3) | Off: app water cards deprecated (not offered); the system `measure_water_changed` card and tags vanish with the capability; hot-water cards untouched. On: the system card and tags appear (Homey-owned). The app trigger only fires from `CapabilityWriter` changes, so it cannot fire while off. |
| Old Flows when off | App edits no Flow (FR-54 AC3). Homey breaks Flows on removed capabilities (how it shows that: 04 U4). A legacy `update_water` Flow gets `feature.guard()`: rejection "ToonWater is not enabled for this device", zero requests (FR-54 AC2; fallback CD-2 = resolve as no-op). `hotwater_dispensing` and `alarm_water_changed` always work. |

Cost of DB-3: with ToonWater on there is no dedicated app card for water today/total (sub-capabilities get no system cards, 02 HS-35) and `update_water` is not offered to new Flows. No FR requires one; adding cards needs `04:HW-09`.

## 6. Pairing

`onPair(session)` registers `testConnection({address})` and `buildDevice({name,id,address,toonwater})`; the view calls `Homey.emit`, then `Homey.createDevice(record)` (Promise API, vanilla JS, `Homey.__`, Style Library; 02 HS-50/51). `testConnection`: `normalizeAddress` (localized error, no request on empty input; FR-01 AC3, FR-03) -> `getThermostatInfo()` (5 s) -> needs `currentTemp` and `currentSetpoint`, else "does not look like an open Toon" (FR-02 AC3) -> `{currentTemp, currentSetpoint, programState, toonwater:'detected'|'absent'|'unknown'}`; the water probe has its own 3 s and can never fail the test (FR-61 AC2/3). Connect stays disabled until a test passed and re-disables when the address changes (FR-01 AC2, FR-02 AC5). `buildDevice` trims `data.id`, rejects empty, keeps `{id}` and `address` (04 C-ID-3). Duplicate-id messaging is hardware (FR-04 AC2).

## 7. Flow cards

All cards in `driver.flow.compose.json`; Compose adds the `device` arg (`driver_id=open-toon`), ids/args unchanged (02 HS-12). `flow/register.js` maps card id -> runtime method in one table; listeners are `async`.

* **Triggers by change detection**: `TRIGGERS = [{cardId, capabilities, tokens, source:'app'|'homey', onlyIf}]`. `triggers.fire(changes)` groups per card (so `meter_power_changed` fires once with peak+off-peak in kWh, 3 decimals, token title "kWh", FR-70 AC5), calls `getDeviceTriggerCard(id).trigger(device, tokens).catch(log)` (listener errors never stop polling, FR-70 AC3). `alarm_water_changed` keeps token `alarm_water.hotwater`. New `burner_state_changed` (arg `state` any/off/heating/hot_water/preheating, filtered in `registerRunListener((args, st) => ...)`) and `burner_state_is` (FR-32). `temperature_state_changed` is `source:'homey'` (DB-6).
* **Conditions**: pure over `normalizeDropdown(arg)` (string or `{id}`, 04 U7), always boolean (`null` -> `false`, FR-72); `temperature_state_is` gains `vacation`.
* **Actions**: `set_temperature_state` (`resume_program` undefined -> `yes`), `enable_program`, `disable_program` resolve only after the Toon answered and `result` was checked, else reject localized (FR-73). `update_status` ("Update now") = `rt.refresh(all enabled)`, rejects only if `thermostat` fails; `update_powerusage` / `update_metertotals` / `update_water` refresh their own group and reject if it fails (water 404 excepted; 04 B-2, R-37). `refresh()` joins an in-flight cycle or runs a targeted one (FR-74 AC3).
* **Deprecated** (`deprecated:true`, listeners kept): `meter_gas_changed`, `measure_water_changed`, `update_powerusage`, `update_metertotals`, `update_water`. Dropdown values carry `title` and `label` (04 R-17). `set_temperature_state.titleFormatted` gets `[[state]]` + `[[resume_program]]`; nl `!{{is|is niet}}` (FR-73 AC4, FR-77).

## 12. Main risks and open points

1. **Weight for a ~600-line app**: about 35 small files and 4 layers cost a part-time maintainer onboarding time. Mitigation: layering test, small files; it is not a cure. A/C are lighter.
2. **The fake Homey encodes our beliefs.** Unknowns can be wrong identically in code and fake: new-setting defaults on upgrade (`U3`), `store`/`capabilities` honoured by `createDevice`, `setSettings` on `label` items, `this.homey.app` and `driver.manifest` access, `onSettings` throw semantics, Flow-editor behaviour. Settled only by `01:HW-01/05/06/12/13`, `04:HW-03/04/06/08/09`.
3. **DB-3 vs the owner's wording**: "water cards appear when on" is met by Homey's system card only; `update_water` visible when on needs `04:HW-09` (compose-only change).
4. **Unverified Toon facts**: 404 for a missing add-on (`01:HW-07`); meter discovery with no real `getDevices.json` (`01:HW-02`, ambiguous `HAE_METER_v*` types, 03 4.4); `resume_program=no` (`01:HW-04`); `Accept-Encoding: identity` and the 30 s load on a Toon 1 (`01:HW-10`); nightly reboot flapping availability.
5. **Preemption plus per-address gate** is the most likely place for a subtle concurrency bug and is covered by fake-clock scenarios only, not real timing.
6. **Behaviour changes needing changelog lines**: `update_*` now reject, dormant triggers start firing (04 R-09/R-11/R-13), gas/kWh gain decimals (FR-114), possible trigger double-fire until `04:HW-06`.
7. **Floor `>=12.9.0`** excludes older firmware (04 R-26); release as `>=2.0.0`, installed with `homey app install`, never `--clean` (04 R-31).
8. **Hardware-only**: pairing in web/mobile, Flow-editor visibility and Flow state on remove/re-add, Insights continuity, real `/water.html` status/units/staleness, `burnerInfo`/`programState`/`resume_program`, `getDevices.json` per Toon, unplug/re-plug, 24 h load, Homey Energy, upgrade over a real baseline, and the Node 22 re-run of the fetch checks.
